# UBPD PC REMOTE (C#)

Настольное приложение для управления UBPD **с ПК по Bluetooth** (классический
SPP / «Bluetooth Serial», без Wi-Fi и точки доступа).

## Что умеет
- поиск Bluetooth-устройств и подключение к UBPD (SPP);
- **текст на экран** OLED на N секунд — на весь экран крупным шрифтом (33 px,
  кириллица, 3–6 символов в строку), без мигания; стереть;
- **GIF/анимация на экран**: GIF декодируется и кодируется в кадры 1-бит 128×64
  **на ПК**; ESP получает готовые кадры и просто блитит их (без вычислений);
- запрос статуса (версия, uptime, память, число найденных, счётчик сообщений).

## Сборка и запуск
```
cd pc/UbpdRemote
dotnet build -c Release
dotnet run -c Release
```
Требуется .NET SDK (7 или новее). Первый запуск спаривает UBPD в Windows
(в настройках Bluetooth) — либо подключение идёт напрямую через SPP.

## Протокол (JSON, одна строка на сообщение, `\n` в конце)
| От ПК | Смысл |
|---|---|
| `{"cmd":"oled","text":"...","secs":5}` | текст на экран на N секунд |
| `{"cmd":"clear"}` | стереть |
| `{"cmd":"state"}` | запрос статуса |
| `{"cmd":"anim","n":<кадров>}` | дальше идут `n × 1024` байт кадров (бинарно) |

Ответы прибора: `{"ok":1,...}`.

## Формат кадра (важно)
Кадр = 1024 байта в раскладке буфера U8g2/SSD1306 (родная GDDRAM):
```
byte[(y>>3) * 128 + x], бит (y & 7) = пиксель (x,y)
```
То есть байт на каждую колонку из 8 пикселей по вертикали, 8 «страниц» по 128 байт.
Логика преобразования — в `Oled.cs` (`Pack`).

## Файлы
- `BtLink.cs` — SPP-соединение (32feet.NET) и отправка.
- `Oled.cs` — GIF/картинка → кадры 1-бит 128×64.
- `MainForm.cs` — интерфейс (вкладки: Текст, GIF, Статус).
- `Program.cs` — запуск.

## Заметки
- Пакет `InTheHand.Net.Bluetooth` (32feet.NET). Целевая платформа —
  `net7.0-windows` (у `net8.0-windows` в пакете нет Windows-реализации).
- Радио у ESP32 одно: пока идёт SPP, BLE-скан и классический поиск спят
  (в прошивке они глушатся в режиме PC REMOTE).
