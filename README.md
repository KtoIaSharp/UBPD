# UBPD — Unknown Bluetooth Pocket Device

**Карманный Bluetooth-инструмент на классическом ESP32**

![Версия](https://img.shields.io/badge/version-0.5.4-blue)
![Платформа](https://img.shields.io/badge/platform-ESP32--WROOM--32-red)
![ESP-IDF](https://img.shields.io/badge/ESP--IDF-4.4-green)
![Экран](https://img.shields.io/badge/display-OLED_128x64-lightgrey)
![Лицензия](https://img.shields.io/badge/license-MIT-yellow)

BLE-сканер · классический Bluetooth (BR/EDR) · RSSI-радар · A2DP-плеер и AVRCP-пульт ·
локальный WEB UI · OLED 128×64 · интерфейс на русском

</div>

---

UBPD — это устройство и прошивка для **изучения Bluetooth-эфира вокруг себя** и
**наблюдения за своими устройствами**. Всё живёт на одной плате ESP32 с экраном
128×64: список найденного, карта силы сигнала, слежение за избранным, свой
BLE-идентификатор, плеер на свои наушники и канал управления с ПК.

Код написан **с нуля**. Прежний `BLE.ino` (iBeacon-спам со случайным MAC) удалён:
он подменял адрес устройства и засорял эфир, что к концепции UBPD не относится.

## Возможности

| Блок | Что умеет |
|---|---|
| **RADAR** | Пиксельная карта RSSI: кольца шкалы (−45 центр → −91 край, 2 dBm = 1 px), развёртка, выбор цели, источник BLE или Wi-Fi |
| **SCANNERS** | Три сканера в одной вкладке: `SCANNER` (классика + BLE в одном списке), `CLASSIC SCANNER`, `BLE SCANNER`; карточка устройства, CONNECT, WATCH |
| **DEVICE / DEVICE TYPE** | Тип устройства с вероятностью (`ТИП: Audio 78%`), MAC, список GATT-сервисов после подключения |
| **WATCH** | До 16 своих устройств в NVS: FOUND/GONE, живой RSSI, LED/вибро и сообщение при появлении |
| **TIMED SCAN / SLEEP WATCH** | Цикл «скан → пауза» с логом находок; ночной режим с погашенным экраном и редкими сканами |
| **IDENTITY / BLE FUN** | Смена своего BLE-имени (в т.ч. кириллица) и 8 имён с режимами SINGLE / CYCLE / RANDOM — реклама своего же устройства |
| **REMOTE** | Классический поиск своих наушников/колонки, **A2DP-плеер** WAV с SD и **AVRCP-пульт**; окно входа на любое Bluetooth-подключение к прибору |
| **WEB UI** | Локальная точка доступа `UBPD-XXXX` и страница со сканом, WATCH, IDENTITY, BLE FUN, настройками и CSV-логом RSSI |
| **MANAGER** | Правило фона: ни одна функция не живёт в фоне сама по себе — только по разрешению (4 состояния на функцию) |
| **DIAGNOSTICS / SETTINGS** | Батарея, RAM, flash, счётчики, версия и дата сборки; вибро, порог RSSI, сон, яркость, AP, сброс NVS |

Дополнительно: таблица производителей Bluetooth SIG (`companies.h`, **4022 записи**) —
любое устройство показывает вендора (`Apple`, `Samsung`, `Espressif`, а если ID
неизвестен — `0x0837`).

## Железо и распиновка

Плата: **ESP32-WROOM-32** (ESP32-D0WD-V3, rev 3.1), MAC `58:2a:bd:d8:41:b4`,
USB-UART **CH340**, порт **COM3**.

| Модуль | Пины | Статус |
|---|---|---|
| OLED SSD1306 128×64, 4 пина (I2C) | SDA → **GPIO21**, SCL → **GPIO22**, VCC → 3V3, GND → GND | есть |
| Кнопки UP / DOWN / OK / BACK | **GPIO32 / 33 / 25 / 26** → GND (`INPUT_PULLUP`) | **не подпаяны** |
| Светодиод | **GPIO2** (встроенный) | есть |
| Вибромотор (PWM-модуль) | сигнал → **GPIO27**, LEDC ~20 кГц | есть; при включении — 3 с вибро |
| microSD (SPI) | CS → **GPIO15**, MOSI → **23**, MISO → **19**, SCK → **18**, питание → 3.3 В, перемычка 3V3 | модуль есть, контакт нестабилен |
| Батарея Li-Po + TP4056 + buck-boost 3.3 В | питание на пин `3V3`, делитель → **GPIO34** (`BATT_ENABLED`) | не подпаяно |
| nRF24 (план 0.6) | SPI + CE/CSN | заказано |

Свободные пины: **4, 13, 14, 16, 17**. Кнопок пока нет — управление дублируется по Serial.

## Быстрый старт: сборка и заливка

Основная сборка — **ESP-IDF v4.4**, Arduino-ядро подключено компонентом
(`components/arduino`), U8g2 — тоже (`components/u8g2`).

```cmd
:: 1. окружение ESP-IDF
C:\esp\esp-idf\export.bat
cd /d C:\Users\user\Desktop\FakeWiFi\BLE

:: 2. сборка и заливка
idf.py build
idf.py -p COM3 flash
```

Быстрый хелпер (сам ставит PATH и зовёт export):

```cmd
C:\Users\user\Desktop\FakeWiFi\_tools\build_idf.cmd build
C:\Users\user\Desktop\FakeWiFi\_tools\build_idf.cmd -p COM3 flash
```

> ⚠️ **Путь — только латиница.** ESP-IDF не собирается, если в пути есть кириллица,
> поэтому рабочая папка переименована в `...\FakeWiFi\BLE` (было `Фейк вифи\BLE`).

Подробности переноса и все найденные грабли — в [`README-IDF.md`](README-IDF.md).

## Управление

Кнопки (когда подпаяны): `UP` / `DOWN` / `OK` / `BACK`, долгое нажатие — `HOLD`.
Пока кнопок нет, всё то же доступно по Serial:

```text
u / w        UP              l        OK (долгое нажатие)
d / s        DOWN            m        BACK (долгое нажатие)
o / Enter    OK              h        справка
b / Esc      BACK
```

Долгие нажатия: радар — опции (источник BLE/Wi-Fi, развёртка); WATCH — удалить
устройство; TIMED SCAN — старт; главное меню — тест вибро (`p` в Serial).

## Архитектура проекта

Один модуль — один `.cpp`. Объявления функций между модулями — в `main/ubpd.h`
(реестр: добавил функцию — допиши прототип).

```text
app_main.cpp   setup()/loop(): hardwareInit, displayInit, sdInit, uiInit, storageLoad,
               BLEDevice::init("UBPD"), classicInit, splash, тост с инфо о SD
config.h       пины, лимиты, флаги, типы (в т.ч. AppState), версия
globals.h/.cpp общие переменные (extern + одно определение)
ubpd.h         прототипы функций между модулями
display.cpp    U8g2, разметка экрана, splash
hardware.cpp   кнопки, LED, батарея, Serial
scanner.cpp    BLE-скан (esp_ble_gap), кэш устройств, WATCH, CONNECT, реклама
btclassic.cpp  классический Bluetooth (esp_bt_gap): поиск, Class of Device, имена
radar.cpp      пиксельный радар RSSI
sleep.cpp      SLEEP WATCH (esp_sleep)
buzzer.cpp     вибромотор (ШИМ, LEDC) — haptic
wifi.cpp       esp_wifi + esp_netif (скан, точка доступа)
web.cpp        локальный WEB UI (esp_http_server)
storage.cpp    NVS (настройки, избранное)
sdcard.cpp     SD по SPI: монтирование, /UBPD, лестница скоростей
player.cpp     REMOTE: A2DP-источник (WAV) + AVRCP-контроллер
ui.cpp         меню и все экраны
companies.h    таблица производителей Bluetooth SIG (4022 записи, сгенерирована)
web_page.h     HTML/JS страницы WEB UI
```

**Зависимости** (`main/CMakeLists.txt`): `arduino u8g2 bt json fatfs sdmmc nvs_flash
esp_http_server esp_wifi driver`; для `main` ослаблен `-Werror=format-truncation`
(подписи для OLED живут в 26-байтных буферах, обрезка кириллицы — задумка).

**Ключевые настройки** (`sdkconfig.defaults`):

| Параметр | Зачем |
|---|---|
| `CONFIG_BT_ENABLED`, `CONFIG_BT_BLUEDROID_ENABLED`, `CONFIG_BTDM_CTRL_MODE_BTDM` | BLE **и** классика на одном чипе |
| `CONFIG_BT_CLASSIC_ENABLED`, `CONFIG_BT_A2DP_ENABLE` | BR/EDR и A2DP-источник (плеер/пульт) |
| `CONFIG_BT_SPP_ENABLED=n` | SPP выключен с 0.5.3: PC REMOTE удалён, SPP-сервер больше не нужен |
| `CONFIG_ESP32_WIFI_IRAM_OPT=n`, `CONFIG_ESP32_WIFI_RX_IRAM_OPT=n` | SD-стек переполнял `iram0_0_seg` (~1.6 КБ) |
| `CONFIG_FATFS_LFN_HEAP=y`, `CONFIG_FATFS_API_ENCODING_UTF_8=y` | длинные имена и кириллица в названиях файлов |
| `CONFIG_COMPILER_OPTIMIZATION_SIZE=y`, `CONFIG_ESP32_DEFAULT_CPU_FREQ_240=y` | размер кода и плавность отрисовки/BLE |
| `CONFIG_FREERTOS_HZ=1000`, `CONFIG_AUTOSTART_ARDUINO=y` | требования Arduino-ядра |

**Разделы** (`partitions.csv`, схема «huge_app»): `nvs` 20 КБ · `otadata` 8 КБ ·
`app0` **3 МБ** (`0x300000`) · `spiffs` 896 КБ · `coredump` 64 КБ.
Образ последней сборки `build/ubpd.bin` — **1 603 872 Б (≈1.53 МиБ)**: ≈51 % слота,
~49 % свободно (после удаления PC REMOTE/SPP образ стал на ~56 КБ меньше).

## SD-карта

Карта монтируется по SPI (VSPI) при старте, **не форматируется**:

```text
SPI: CS=15  MOSI=23  MISO=19  SCK=18   (питание модуля → "3.3", GND → GND, перемычка 3V3)
[i] SD: OK 64000MB
[i] SD: /sdcard/UBPD  →  sounds/ logs/ scripts/ ble_names/
```

* **Требуется честная FAT32** — exFAT ESP-IDF 4.4 не читает. Если ФС битая, помогает
  полное переформатирование (Rufus / guiformat): бывает, `mkdir` рапортует успех, а каталога нет.
* Скорость SPI подбирается лестницей **20 / 10 / 4 / 1 МГц** (для стриминга звука нужно ≥ 4 МГц).
* Карты нет — прибор пишет «SD нет» и работает дальше, не падает.
* Ошибки `send_if_cond … 0x108/0x107`, `sdmmc_card_init failed (0x107)`, MISO висит в 1 —
  это **питание/контакт модуля**, а не прошивка.

## REMOTE: плеер и пульт

Отдельный режим: BLE-скан и точка доступа глушатся, радио целиком отдаётся классике.

* `REMOTE:BT` — список своих устройств (классический поиск). `OK` — подключить,
  `HOLD OK` — переключить режим подключения:
  * **FULL** — A2DP + AVRCP: играем свой WAV на подключённое устройство;
  * **CTRL** — только AVRCP: управляем чужим плеером (например, телефоном) без своего звука.
* `REMOTE:PLAY` (FULL) — **экран-«проигрыватель»**: имя трека крупным шрифтом, полоса
  прогресса, `ТРЕК n/N`. `UP/DOWN` — трек, `OK` — play/pause, `HOLD OK` — рандом,
  `BACK` — к списку устройств, **`HOLD BACK` — выход из REMOTE**.
* `REMOTE:CTRL` — AVRCP-пульт: **список действий** (`UP/DOWN` — выбор, `OK` — выполнить):
  громкость +/−, play/pause, следующий, предыдущий, **MUTE**.

**Память трека.** Последний выбранный трек хранится в NVS: после перезагрузки
REMOTE играет его же, а не первый из списка.

**Диагностика звука.** Счётчик недоборов буфера (`XRUN`) виден на второй странице
`DIAGNOSTICS` — по нему понятно, заикается звук на самом деле или нет (раньше это
приходилось угадывать на слух).

**Окно входящего подключения.** Прибор всегда `connectable` и `discoverable` под
именем `UBPD`, поэтому **любое** входящее Bluetooth-подключение (ловится на уровне
линка, ACL) поднимает поверх любого экрана окно: `FULL: играть` / `CTRL: пульт` /
`ОТКАЗ: не надо`; `BACK` — отказ и возврат на прежний экран. Заголовок показывает
имя или MAC, вход сопровождается вибро. `ОТКАЗ` ничего не разрывает: публичного API
«закрыть classic ACL» в ESP-IDF 4.4 нет — линк без единого профиля обычно уходит сам.
Своё собственное подключение (REMOTE подключается к наушникам) окно не вызывает.

**Звук стримится прямо с SD**: отдельная задача читает файл в кольцевой буфер (24 КБ),
A2DP-колбэк забирает кадры и приводит любой формат к **16-бит стерео 44100**
(8/16/32-бит, моно/стерео, любая частота). Размер трека **не ограничен кучей** —
проверен файл 44.7 МБ (`44100Hz 2ch 16bit`). Если файлов нет — играет тестовый тон 440 Гц.

**Окно входящего подключения.** Если к прибору по Bluetooth подключается постороннее
устройство, поверх любого экрана всплывает окно: `FULL: играть` / `CTRL: пульт` /
`ОТКАЗ: не надо`; `BACK` — отказ и возврат на прежний экран.
Заголовок показывает имя или MAC, вход сопровождается вибро.

## WEB UI: точка доступа

`MENU → WEB UI → OK`. Поднимается точка доступа `UBPD-XXXX` (открытая; в SETTINGS
можно включить пароль `ubpd1234`), адрес **192.168.4.1**.

С телефона доступны: скан вкл/выкл, WATCH, IDENTITY, BLE FUN, настройки, секция
**КЛАССИЧЕСКИЙ BLUETOOTH** (старт/стоп, таблица, слежение), CSV-лог RSSI, сброс NVS,
перезагрузка. Из API: `GET /api/state` (в т.ч. `cls`, `clsCount`, `classic`),
`POST /api/classic?on=1|0`.

> Wi-Fi и BLE делят один радиомодуль: с включённой точкой доступа скан идёт медленнее,
> а RSSI грубее — для лабораторных измерений AP лучше выключать.

## Две сборки: ESP-IDF и Arduino

Логика у обоих вариантов **одна и та же**, отличается система сборки и служебные части.

| | ESP-IDF (основная, эта папка) | Arduino (`legacy/arduino-0.4/`) |
|---|---|---|
| Сборка | `idf.py build` / `-p COM3 flash` | `arduino-cli compile/upload` |
| Ядро | `esp32:esp32 2.0.17` как компонент `components/arduino` | `esp32:esp32 2.0.17` |
| Настройки | `nvs` напрямую | `Preferences` (обёртка NVS) |
| WEB UI | `esp_http_server` | Arduino `WebServer` |
| Wi-Fi | `esp_wifi` + `esp_netif` | класс `WiFi` |
| Вибро | `driver/ledc` (ШИМ) | `tone()` |
| Размер образа | ~1.6 МБ (`-Os`) | ~1.72 МБ |
| Файлы | `main/*.cpp`, один модуль = один файл | `*.ino`, склейка в один |

Прежняя Arduino-версия целиком лежит в `legacy/arduino-0.4/` и остаётся эталоном логики:
правишь смысл там — потом переносишь в `main/`.

## Рамки проекта

* Работаем только с **открытыми (broadcast) данными** и с **добровольными подключениями**.
* Нет подмены MAC, нет деаутентификации, нет эксплойтов, нет «глушилок».
* `BLE FUN` рекламирует **своё собственное** устройство: MAC чипа не меняется,
  меняется только имя в рекламном пакете.
* `CONNECT` подключается только к устройствам, которые сами принимают соединение,
  и только читает **открытые** GATT-сервисы — ничего не пишется.
* Запрос имени по классике — стандартный LMP-запрос, как при поиске устройств в телефоне:
  без спаривания, без открытия профилей, без чтения данных (отключается `CLASSIC_NAME_REQ 0`,
  за цикл поиска имён запрашивается не больше `CLASSIC_NAME_MAX`).
* Используй прибор там, где сканирование эфира разрешено, и только со своими устройствами.

## Честные технические оговорки

* **Радар — не направление.** Один ESP32 не может определить, откуда идёт сигнал:
  показана только сила (2 dBm = 1 px, −45 dBm — центр, −91 dBm — край, см. `main/radar.cpp`),
  а угол точки — стабильный хэш MAC-адреса, а не пеленг.
* **Одно радио.** Классический ESP32 делит радиомодуль: BLE, классика и Wi-Fi не работают
  одновременно. Поэтому в радаре источник либо BLE, либо Wi-Fi; в REMOTE
  радио отдано классике; общий `SCANNER` гоняет BLE и классику по очереди (6 с на режим).
* **Классика и BLE конкурируют.** Пока открыт `CLASSIC SCANNER`, BLE-скан приостановлен,
  и наоборот — так надёжнее, чем гнать оба режима разом.
* **Имя по классике приходит не сразу.** Поиск — эфирный опрос (4 × 1.28 с ≈ 5 с),
  имя запрашивается после цикла, ещё ~1–2 с. Устройство видно через 1–2 с (тип из
  Class of Device и `XX:XX`), имя — через ~6 с, потом берётся из кэша.
* **CONNECT может «замереть» до ~20 с** — это таймаут стека BLE, если устройство недоступно.
* **Почему у BLE-устройства нет имени.** Имя — необязательное поле рекламы: Apple-гаджеты,
  трекеры, ТВ-пульты часто его не передают. Тогда показывается то, чем устройство всё же
  представилось: производитель по Company ID и последние байты MAC (`AA:BB`). Это не ошибка
  сканера — проверено дампом сырых пакетов (AD-типов `0x08`/`0x09` там просто нет).
* **DEVICE TYPE и CLEAR SCAN — эвристика**, а не чтение этикетки: по appearance, профилям,
  имени и производителю (поэтому `ТИП: Audio 78%` и метки с `?`).
* **WEB UI и сон.** Точка доступа не выживает в light sleep — при входе в `SLEEP WATCH`
  она выключается (в Serial пишется почему). Если BLE-стек не даёт уйти в сон, вместо сна
  будет пауза `delay` (об этом тоже пишется один раз).
* **Фон конфликтует с вкладкой**: приоритет всегда у той вкладки, куда ты зашёл —
  фоновая реклама/скан временно глушатся и поднимаются после выхода.
* **BLE FUN**: имя в рекламе ≤ 24 байта (кириллица = 2 байта на символ), лишнее режется
  по границе UTF-8. `TEMP_ENABLED 0` по умолчанию (`temperatureRead()` есть не везде),
  `BATT_ENABLED 0` — пока не подпаян делитель.

## Известные проблемы

| Проблема | Причина / что делать |
|---|---|
| `sdmmc_card_init failed (0x107)`, SD «то видна, то нет» | Контакт/питание SD-модуля: проверить пайку, GND и перемычку 3V3. Без карты плейлист пуст и играет тест-тон 440 Гц (его легко принять за «гудение») |
| Звук не идёт в FULL | WAV должен быть настоящим PCM (RIFF/WAVE, `fmt `/`data`), 16-бит 44100 стерео; MP3/FLAC с расширением `.wav` парсер отвергнет (в Serial — `не WAV`) |
| Кнопок нет | Управление по Serial (см. [Управление](#управление)) |
| Кириллица в пути сборки | ESP-IDF падает — путь проекта только латиница |

```text
[i] REMOTE: <файл>  <байт>  <Гц> <каналы> <бит> tag=<..> heap=<..>
Пример: 44748558 б  44100Hz 2ch 16bit tag=1  heap=72220
```

### v0.5.4 — вибро при включении

Мотор припаяли, и теперь при подаче питания прибор **вибрирует 3 секунды** — сразу
понятно, что вибро живое и припаяно правильно, ещё до загрузки экрана.

* длительность задаётся `BOOT_VIBRO_MS` в `main/config.h` (`0` — выключить);
* импульс **неблокирующий**: мотор включается сразу, а гасит его `buzzerTick()` в
  `loop()` — загрузка (экран, SD, BLE/классика) из-за вибро не ждёт;
* сила и схема берутся из `config.h` (`BUZZER_ACTIVE` / `BUZZER_INVERT`), а не из NVS:
  настройки из памяти читаются позже, а вибро нужно ровно в момент включения.
  Настройка `ВИБРО` в SETTINGS на приветственный импульс не влияет — это проверка
  железа, а не событие;
* `buzzerApplyIdle()` (гасит мотор после загрузки настроек) приветственный импульс
  не прерывает, а `buzzerSilence()` — прерывает.

В Serial это видно так:

```text
[i] ВИБРО: приветствие 3000 мс (сильно, норма)
...
[i] ВИБРО: приветствие закончено
```

### v0.5.3 — минус PC REMOTE + мелочи плеера

**PC REMOTE удалён целиком** — признан тупиковой веткой. Убраны: `main/pcremote.cpp`
(SPP-сервер и JSON), вкладка меню `PC REMOTE`, экран статуса, HTTP-путь `POST /api/oled`
с полноэкранным текстом, а `CONFIG_BT_SPP_ENABLED` переведён в `n` (A2DP/AVRCP от SPP
не зависят). Настольное приложение на C# переехало в `legacy/pc-remote/` — рядом со
старой Arduino-сборкой, которая теперь лежит в `legacy/arduino-0.4/`.

**Окно входа теперь на любое Bluetooth-подключение, а не на SPP.** Прибор сам держит
имя `UBPD` и режим `connectable + discoverable` (перенесено из `pcremote.cpp` в
`btclassic.cpp`), а входящее подключение ловится на уровне линка —
`ESP_BT_GAP_ACL_CONN_CMPL_STAT_EVT`. Вариантов стало три: `FULL: играть`,
`CTRL: пульт`, `ОТКАЗ: не надо`. Своё собственное подключение (REMOTE к наушникам)
окно не вызывает, иначе оно всплывало бы поверх собственного плеера.

**Мелочи плеера (без проверки на железе):**
* счётчик недоборов буфера **XRUN** в `DIAGNOSTICS` — заикание стало числом;
* **MUTE** в AVRCP-пульте; экран `REMOTE:CTRL` превратился в список действий
  (громкость, play/pause, next, prev, mute) — раньше все кнопки были заняты;
* **последний трек помнится в NVS** (`trk`) и восстанавливается при входе в REMOTE.

### v0.5.2 — плеер: стриминг звука с SD

Экран **FULL** переделан в «проигрыватель» (имя трека, полоса прогресса, номер из
плейлиста — не список), а звук с SD теперь реально стартует: команда `START` шлётся в
момент фактического поднятия A2DP-линка, а не сразу после запроса на подключение
(раньше она уходила «в пустоту» и музыка молчала). Управление: `UP/DOWN` — трек,
`OK` — play/pause, `HOLD OK` — рандом, `BACK` — к списку устройств,
**`HOLD BACK` — выход из REMOTE**. Во время игры/пульта классический поиск глушится.

**Звук стримится прямо с SD**: отдельная задача читает файл в кольцевой буфер (24 КБ),
A2DP-колбэк забирает кадры и приводит любой формат к 16-бит стерео 44100. Размер трека
больше **не ограничен кучей** (прежняя загрузка в RAM падала на файлах > ~100 КБ — отсюда
тишина и тест-тон). Разбор WAV по чанкам `fmt `/`data`. Скорость SPI SD — лестница
20/10/4/1 МГц. Имена файлов читаются в **UTF-8** (длинное `Nautilus-Pompilius-…`, а не
`NAUTIL~1.WAV`): включён `CONFIG_FATFS_API_ENCODING_UTF_8`, буферы под LFN увеличены.
Проверен файл 43–45 МБ. Исправлен краш в `sdInit` (результат `spi_bus_initialize`
перетирал `ret`, из-за чего цикл монтирования не запускался).

### v0.5.1 — всплывающее окно входящего Bluetooth-подключения

> ⚠️ Реализация 0.5.1 была привязана к SPP-серверу и в **0.5.3 переделана**: триггером
> стало любое ACL-подключение, вариант «ПК: SPP-терминал» убран (см. v0.5.3 выше).

Когда к прибору по классическому Bluetooth (SPP-сервер `UBPD`) подключается постороннее
устройство (телефон, ПК), прошивка **сама** показывает поверх любого экрана окно выбора:

* **FULL: играть** — A2DP + AVRCP: сразу отдаём наш WAV на подключившееся устройство;
* **CTRL: пульт** — только AVRCP: управляем подключённым устройством без воспроизведения;
* **ПК: SPP-терминал** — оставить соединение как канал PC REMOTE (текст/GIF на экран);
* **ОТКАЗ (отключить)** / `BACK` — разорвать соединение и вернуться на прежний экран.

Заголовок окна показывает имя или MAC подключающегося устройства, вход сопровождается
коротким вибро. Радио на время окна отдано классике. Заодно починен `pcremote.cpp`
(объявлены `sIncoming`/`sPeer`, добавлены `pcRemoteTakeIncoming()`/`pcRemoteDisconnect()`,
ловим `ESP_SPP_SRV_OPEN_EVT`).

### v0.5.0 — REMOTE: пульт и плеер + вибро

Крупный релиз. **REMOTE** — отдельный режим (BLE/Wi-Fi глушим, радио отдаём классике),
три экрана: `REMOTE:BT` (список своих устройств, `HOLD OK` — FULL/CTRL),
`REMOTE:PLAY` (плейлист `*.wav` из `/UBPD/sounds`), `REMOTE:CTRL` (AVRCP-пульт:
громкость, play/pause, next/prev). Звук — **A2DP-источник** на свои наушники, WAV играется
как есть (16-бит PCM, без декодера), иначе тест-тон 440 Гц.

**Вибромотор вместо пищалки** (GPIO27, ШИМ ~20 кГц, мотор не пищит): паттерны 1/2/3,
в SETTINGS — `ВИБРО`, `СИЛА ВИБРО`, `ИНВЕРСИЯ`. Включён `CONFIG_BT_A2DP_ENABLE`.
Образ ~1.6 МБ (47 % раздела свободно).

### v0.4.8 — первый мост к SD

Прошивка монтирует microSD по SPI (VSPI) при старте и печатает в Serial, что нашла:
`[i] SD: OK, имя="SD32G", 29820 МБ` → `[i] SD: /sdcard/UBPD`. Карта **не форматируется**,
без карты прибор пишет «SD нет» и работает дальше. После монтирования создаётся структура
`/UBPD/{sounds,logs,scripts,ble_names}`. Требуется честная **FAT32** (exFAT IDF 4.4 не
читает). Побочно: чтобы SD-стек поместился, отключены Wi-Fi IRAM-оптимизации
(`iram0_0_seg` переполнялся на ~1.6 КБ) и включены длинные имена FATFS (LFN).

### v0.4.7 — PC REMOTE: управление с ПК по Bluetooth

> ❌ **Удалено в 0.5.3.** Оставлено как история: SPP-сервер, JSON-протокол и
> C#-приложение (`legacy/pc-remote/`) больше в прошивке не используются.

Управление прибором **только с ПК**, по классическому Bluetooth (SPP), без Wi-Fi и точки
доступа: прошивка поднимает SPP-сервер, приложение на C# (`legacy/pc-remote/`) шлёт JSON —
текст на экран, GIF/анимация (кадры 1-бит 128×64 кодируются **на ПК**), стереть, статус.
Текст показывается на весь экран крупным шрифтом (33 px, кириллица) без мигания.
Вкладка меню **PC REMOTE** показывает статус подключения и счётчик сообщений.

### v0.4.6 — BLE-скан переехал на esp_ble_gap

Скан перестал быть обёрткой Arduino и работает на чистом ESP-IDF: свой GAP-обработчик,
активный скан, ручной разбор рекламного пакета (имя, appearance, TX power, manufacturer
data, сервисы 16/32/128 бит). Поведение то же, но нет аллокации `BLEAdvertisedDevice`
на каждый рекламный пакет. Реклама своего имени и CONNECT остались на Arduino-ядре.

### v0.4.5 — SCANNERS: три сканера в одной вкладке

Появилась общая вкладка **SCANNERS** с тремя подпунктами: `SCANNER` (классика и BLE в
одном списке, классика выше), `CLASSIC SCANNER`, `BLE SCANNER`. `HOLD OK` в общем списке —
поставить/снять слежение. **CLEAR SCAN убран**: то же находит классический поиск (по
Class of Device), а метки типа (`PH`/`HP`/`SP`/`MIC`) показываются прямо в списке.
**MANAGER стал папкой**: внутри — категория «НАСТРОЙКИ ФОНА», рядом «ТОЧКА ДОСТУПА»,
«СОРТИРОВКА», «НАСТРОЙКИ», «СБРОС НАСТРОЕК». Одно радио на два режима: общий `SCANNER`
гоняет BLE и классику по очереди по `COMB_SWITCH_MS` (6 с).

### v0.4.0 — CLASSIC BT: старый Bluetooth

BLE — не весь Bluetooth: телефон с включённым Bluetooth по BLE **молчит**, зато в режиме
«виден всем» честно отвечает на классический поиск. Отдельная вкладка **CLASSIC BT**:
inquiry (4 × 1.28 с ≈ 5 с на цикл), добор имён после цикла (LMP remote name request, без
спаривания), тип из **Class of Device** (не догадка), RSSI, если устройство его сообщило,
постановка на WATCH. **Только обнаружение**: ничего не подключается и не управляется.

### v0.3.0 — MANAGER: правило фона

**Главное правило: функция не работает в фоне сама по себе** — пока MANAGER не разрешил,
любая вкладка живёт только пока ты в ней. Строки `ФОН: BLE FUN / IDENTITY / WATCH /
TIMED SCAN / WEB UI`, плюс «ТОЧКА ДОСТУПА», «СОРТИРОВКА», «НАСТРОЙКИ», «СБРОС НАСТРОЕК».
Четыре состояния фона (`ВЫКЛ` / `ФОН` / `СОН` / `ФОН+СОН`), сохраняются в NVS; при первом
запуске всё стоит в `ФОН`. У RADAR, SCANNERS, DEVICE TYPE, DEVICE и REMOTE переключателя
нет — эти вкладки в фоне не работают по определению. Заодно: WATCH на 16 устройств,
`DIAGNOSTICS` из двух страниц (вторая — `ABOUT`), подтверждения на удаление и сброс.

### v0.2.5 — таблица производителей и CLEAR SCAN

`companies.h` — **4022 записи** из официального списка Bluetooth SIG (Company Identifiers),
сгенерирована скриптом `_tools\gen_companies.ps1` из `company_ids.json` (Nordic
`bluetooth-numbers-database`), поиск двоичный (~12 сравнений), ~65 КБ флеша. Теперь любое
устройство показывает вендора. **CLEAR SCAN** — отдельный режим: в списке только телефоны,
наушники/гарнитуры, колонки и микрофоны (метки `PH` / `HP` / `SP` / `MIC`; без вопроса —
признак заявило само устройство, с `?` — догадка по производителю).

Определение категории по порядку: `appearance` (0x0040–0x007F телефон, 0x0880–0x08BF
наушники, 0x08C0–0x08FF слуховой аппарат, 0x0800–0x083F колонка, 0x0840–0x087F микрофон) →
classic-аудио профили в 16-битных UUID (`0x1108`/`0x111E`/`0x1112`, `0x110B`, `0x110A`/`0x110C`) →
имя в рекламе (airpods/buds/headphones, jbl/flip/boombox, rode/wireless go, iphone/galaxy/pixel) →
производитель (уже догадка, поэтому с `?`). Устройство без имени, appearance и с известным
производителем в CLEAR SCAN не попадёт — это ожидаемо.

  переезде она осталась в старой папке. Перенести: закрыть Crush и выполнить
  `..\_tools\move_chat.ps1` (копирует базу, сверяет размер и убирает старую папку).
