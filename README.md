# UBPD — Unknown Bluetooth Pocket Device (v0.4.0)

> Карманный инструмент для изучения BLE-устройств поблизости и наблюдения за своими устройствами.
> Платформа: классический ESP32 · Экран: OLED 128×64 · Интерфейс: русский

Карманный гаджет на **классическом ESP32**: BLE-сканер, **классический Bluetooth (BR/EDR)**,
пиксельный RSSI-радар, подписка на свои устройства, смена своего BLE-имени, диагностика — на OLED 128x64.

Код написан **с нуля**. Прежний `BLE.ino` (iBeacon-спам со случайным MAC) удалён:
он подменял адрес устройства и засорял эфир, что к концепции UBPD не относится.

## Две сборки: Arduino и ESP-IDF

Логика у обоих вариантов **одна и та же**, отличается только система сборки и то,
чем собраны служебные части.

| | ESP-IDF (основная, эта папка) | Arduino (`legacy 0.4/`) |
|---|---|---|
| Сборка | `idf.py build / -p COM3 flash` | `arduino-cli compile/upload` |
| Ядро | `esp32:esp32 2.0.17` как компонент `components/arduino` | `esp32:esp32 2.0.17` |
| Настройки | `nvs` напрямую | `Preferences` (обёртка NVS) |
| WEB UI | `esp_http_server` | Arduino `WebServer` |
| Wi-Fi | `esp_wifi` + `esp_netif` | класс `WiFi` |
| Пищалка | `driver/ledc` | `tone()` |
| Размер образа | ~1.47 МБ (`-Os`) | ~1.72 МБ |
| Файлы | `main/*.cpp`, один модуль = один файл | `*.ino`, склейка в один |

Подробности переноса и грабли — в `README-IDF.md`. Прежняя Arduino-версия целиком
лежит в `legacy 0.4/` и остаётся эталоном логики: правишь смысл там, потом переносишь
в `main/`.

**Про путь:** ESP-IDF не собирается, если в пути есть кириллица, поэтому рабочая папка
переименована в `C:\Users\user\Desktop\FakeWiFi\BLE` (было `Фейк вифи\BLE`).

**История чатов Crush** лежит в `.crush\crush.db` **внутри папки проекта**, поэтому при
переезде она осталась в старой папке. Перенести: закрыть Crush и выполнить
`..\_tools\move_chat.ps1` (копирует базу, сверяет размер и убирает старую папку).

## v0.4.0 — CLASSIC BT: старый Bluetooth

BLE — не весь Bluetooth. Телефон с включённым Bluetooth по BLE **молчит**: он не
рекламируется. Зато в режиме «виден всем» он честно отвечает на классический поиск
и отдаёт своё имя. Поэтому в меню появилась отдельная вкладка **CLASSIC BT**.

```
Меню (14 вкладок):
RADAR · SCANNER · CLASSIC BT · CLEAR SCAN       — обнаружение
DEVICE TYPE · WATCH · TIMED SCAN · SLEEP WATCH  — слежение
BLE FUN · IDENTITY                              — своя реклама
REMOTE · WEB UI · MANAGER · DIAGNOSTICS         — прочее
```

| Что делает CLASSIC BT | Подробности |
|---|---|
| **Поиск (inquiry)** | BR/EDR-опрос эфира: 4 × 1.28 с ≈ 5 с на цикл, дальше цикл повторяется, пока открыта вкладка. Устройство появляется в списке уже через 1–2 с |
| **Имя устройства** | Bluedroid сам имён не отдаёт, поэтому после каждого цикла поиска UBPD добирает имя найденных устройств. Имя приходит через ~6 с после первого обнаружения, дальше берётся из кэша — на экране появляется, например, `realme Buds T200 Lite` |
| **Тип — не догадка** | В ответе приходит **Class of Device**: телефон, компьютер, гарнитура, колонка, микрофон, часы, принтер. Это заявление самого устройства, а не вывод по вендору. Метки те же, что в CLEAR SCAN: `PH`/`HP`/`SP`/`MIC`, плюс `PC`/`NET`/`PRN`/`CAM`/`WCH` |
| **RSSI** | Показывается, если устройство его сообщило; иначе `--`. Сила сигнала по классике приходит не от всех |
| **WATCH** | Устройство из классики ставится на слежение (`HOLD OK` в списке или `OK` на карточке) — WATCH его увидит, даже если по BLE его не видно |

**Что видно только по классике:** телефон, включивший «виден всем»; наушники и
колонки без BLE; автомобильные головные устройства; старые гарнитуры.

### Кнопки

* `OK` в списке — карточка устройства (тип, класс, MAC, RSSI)
* `OK` на карточке — поставить/снять слежение, `BACK` — назад
* `HOLD OK` в списке — поставить/снять слежение сразу

### Честные ограничения (важно)

* **Классика и BLE делят один радиомодуль.** Пока открыта вкладка CLASSIC BT,
  BLE-скан приостановлен, и наоборот — так надёжнее, чем гнать оба режима разом.
* **Устройство должно быть обнаружимым.** Обычный режим «Bluetooth включён» по
  классике тоже почти ничего не отдаёт: телефон нужно перевести в «виден всем».
  Именно поэтому раньше в SCANNER не было имени — в эфире BLE его просто нет.
* **Почему имя не сразу.** Классический поиск — это эфирный опрос: передатчик прыгает
  по 32 каналам, поэтому цикл занимает секунды. Имя спросить можно только **после**
  окончания цикла, и сам LMP-запрос имени занимает ещё ~1–2 с. Итого устройство видно
  через 1–2 с, а имя — через ~6 с. Это разовая задержка: запомненное имя берётся из
  кэша мгновенно, а в списке до этого показываются тип (из Class of Device) и `XX:XX`.
* **Запрос имени** — это стандартный LMP-запрос, который делает любой телефон во
  время поиска устройств. Спаривания не происходит, профили не открываются,
  данные не читаются. Отключается флагом `CLASSIC_NAME_REQ 0` в `config.h`.
  За цикл поиска имён запрашивается не больше `CLASSIC_NAME_MAX` (3).
* **Только обнаружение.** По классике UBPD ничего не подключает и ничем не
  управляет: никаких A2DP/AVRCP-команд, подмены адреса и деаутентификации.

### В WEB UI

Появилась секция **КЛАССИЧЕСКИЙ BLUETOOTH**: кнопки старт/стоп, таблица найденного,
постановка на слежение. В `GET /api/state` добавлены `cls`, `clsCount` и массив
`classic`, есть `POST /api/classic?on=1|0`.

## v0.3.0 — MANAGER: правило фона

**Главное правило: функция не работает в фоне сама по себе.** Пока MANAGER не разрешил —
любая вкладка живёт только пока ты в ней.

Меню стало 13 вкладок (в v0.4.0 добавилась четырнадцатая — CLASSIC BT):

```
RADAR · SCANNER · CLEAR SCAN · DEVICE TYPE      — обнаружение
WATCH · TIMED SCAN · SLEEP WATCH                — слежение
BLE FUN · IDENTITY                              — своя реклама
REMOTE · WEB UI · MANAGER · DIAGNOSTICS         — прочее
```

### MANAGER — строка за строкой

| Строка | Что делает |
|---|---|
| `ФОН: BLE FUN` | разрешить рекламу BLE FUN после выхода из вкладки |
| `ФОН: IDENTITY` | то же для своего BLE-имени |
| `ФОН: WATCH` | мониторинг своих устройств (LED/пищалка) вне вкладки WATCH |
| `ФОН: TIMED SCAN` | продолжать цикл сканов после выхода |
| `ФОН: WEB UI` | держать точку доступа после выхода |
| `ТОЧКА ДОСТУПА` | вкл/выкл AP прямо здесь |
| `СОРТИРОВКА` | `RSSI` / `ИМЯ` / `ТИП` для SCANNER, CLEAR SCAN, DEVICE TYPE |
| `НАСТРОЙКИ` | экран настроек (пищалка, RSSI-порог, сон, яркость, AP, сброс); BACK возвращает в MANAGER |
| `СБРОС НАСТРОЕК` | HOLD OK |

### 4 состояния фона (OK по строке, по кругу; сохраняются в NVS)

| Состояние | Смысл |
|---|---|
| `ВЫКЛ` | только в своей вкладке |
| `ФОН` | работает после выхода из вкладки |
| `СОН` | работает только во время SLEEP WATCH |
| `ФОН+СОН` | и в фоне, и во сне |

При первом запуске (и после сброса) **всё стоит в `ФОН`**. У RADAR, SCANNER, CLASSIC BT,
CLEAR SCAN, DEVICE TYPE, DEVICE и REMOTE переключателя нет вообще — эти вкладки по определению
не работают в фоне, чтобы не плодить непонятные состояния.

### Честные ограничения

* Wi-Fi и BLE делят один радиомодуль: с работающей точкой доступа скан идёт медленнее и RSSI грубее.
* Точка доступа не выживает в light sleep — при входе в SLEEP WATCH она выключается (в Serial пишется почему).
* Фон конфликтует с вкладкой: приоритет всегда у той вкладки, куда ты зашёл — фоновая реклама/скан временно глушатся, а после выхода поднимаются снова.
* Флаги фона применяются сразу (без перезагрузки) и переживают выключение питания.

### Заодно из UX (функция №3)

* WATCH теперь вмещает **16** устройств вместо 8.
* `DIAGNOSTICS` — две страницы: OK переключает (вторая = `ABOUT`: чип, MAC, flash, версия, дата сборки, uptime).
* Подтверждения на удаление из WATCH (HOLD OK) и на сброс настроек — уже есть.

## v0.2.5 — таблица производителей и CLEAR SCAN

| Функция | Что делает |
|---|---|
| **Таблица компаний** | `companies.h` — **4022 записи** из официального списка Bluetooth SIG (Company Identifiers). Сгенерирована скриптом `_tools\gen_companies.ps1` из `company_ids.json` (Nordic `bluetooth-numbers-database`), поиск двоичный (~12 сравнений). Занимает ~65 КБ флеша. Теперь любое устройство показывает вендора: `Apple`, `Samsung`, `vivo`, `Espressif`, а если ID неизвестен — `0x0837` |
| **CLEAR SCAN** | Отдельный режим (меню, пункт 9): в списке только **телефоны, наушники/гарнитуры, колонки и микрофоны**. Метки: `PH` телефон, `HP` наушники, `SP` колонка, `MIC` микрофон. Без вопроса — признак заявило само устройство (appearance/профиль/имя), с `?` — догадка по производителю (например `PH? Apple`, `PH? vivo`) |

Как определяется категория (по порядку, первый сработавший признак):
1. `appearance` устройства: 0x0040–0x007F телефон, 0x0880–0x08BF наушники (earbud/headset/headphones), 0x08C0–0x08FF слуховой аппарат, 0x0800–0x083F колонка (audio sink), 0x0840–0x087F микрофон (audio source).
2. classic-аудио профили в 16-битных UUID: 0x1108/0x111E/0x1112 наушники, 0x110B колонка, 0x110A/0x110C микрофон.
3. имя в рекламе: airpods/buds/headphones, jbl/flip/boombox/soundlink/sonos, rode/wireless go/mikrofon, iphone/galaxy/pixel/sm-/moto.
4. производитель — уже догадка (поэтому с `?`): телефоны Apple/Samsung/Google/Huawei/Xiaomi/OPPO/OnePlus/vivo/Meizu/Motorola/Nokia/LG/Sony/HTC/Lenovo; наушники Sennheiser/Skullcandy/Beats/Audio-Technica + слуховые аппараты; колонки JBL/Bose/Sonos/Klipsch/Marshall/B&O/B&W/Devialet/Libratone/Edifier; микрофоны Shure.

Что честно: это эвристика, а не чтение этикетки. Устройство без имени, без appearance и с неизвестным производителем в CLEAR SCAN не попадёт — это ожидаемо.

## v0.2 — что нового

| Функция | Как пользоваться |
|---|---|
| **LOCAL WEB UI** | Меню → `WEB UI` → OK. Поднимается точка доступа `UBPD-XXXX` (открытая; в SETTINGS можно включить пароль `ubpd1234`), адрес `192.168.4.1`. С телефона: скан вкл/выкл, WATCH, IDENTITY, BLE FUN, настройки, CSV-лог RSSI, сброс NVS, перезагрузка |
| **SLEEP WATCH** | Меню → `SLEEP WATCH` → UP/DOWN интервал (15–300 с) → OK. OLED гаснет, скан раз в интервал, на событие — LED + пищалка. Выход — любая кнопка. Нужно хотя бы одно устройство в WATCH |
| **SETTINGS** | Пищалка вкл/выкл, порог «сильный RSSI», интервал сна, яркость OLED, AP открытая/по паролю, HOLD на последней строке = сброс настроек |
| **Пищалка** | Активный буззер на **GPIO27**. Схема подключения выбирается на самом устройстве: SETTINGS → `ИНВЕРС. ПИЩ.` (см. ниже). Пассивный (пьезо) — `BUZZER_ACTIVE 0` в `config.h`, тогда используется `tone()`. **Быстрая проверка: HOLD OK в главном меню**, кнопка «тест» в WEB UI или команда `p` в Serial — 3 сигнала независимо от настроек |
| **Пищалка: выбор схемы и типа** | SETTINGS, без перекомпиляции, сохраняется в NVS: `ТИП ПИЩАЛКИ` = `АКТИВ` (внутри генератор, даём постоянку) или `ПАССИВ` (пьезо/динамик, нужна частота → `tone()`). `СХЕМА ПИЩ.` = `3.3V (HI)` («+» на GPIO27, «−» на GND) или `5V (LOW)` («+» на 5V/VBUS, «−» на GPIO27, в тишине пин в воздухе). Переключение сразу играет тест — слышно, подошло или нет |
| **Нет 5 В на плате** | Смотри маркировку: `5V`, `5V0`, `VBUS`, `VIN`, `VCC` (на части клонов `VCC` — это 3.3 В!). Если 5 В нет вообще — бери 3V3 и транзистор: база через 1 кОм → GPIO27, эмиттер → GND, коллектор → «−» буззера, «+» буззера → 3V3, схема `3.3V (HI)`. Это и есть правильное решение: GPIO не может отдать 20–30 мА без просадки (пин «садится» до ~2.5 В и 5-вольтовый буззер молчит), а от шины 3V3 через транзистор он получает полные 3.3 В и до 500 мА. Крайние варианты: 5 В с USB (VBUS) или повышающий модуль MT3608 |
| **Если пищит постоянно** | Так ведёт себя буззер, подключённый между 5V и пином: он звучит на LOW, а пин в LOW почти всё время. Лечится переключателем `СХЕМА ПИЩ. → 5V (LOW)` — тогда тишина = high-Z, ток не идёт. Проверка по Serial: `BUZZER_DEBUG 1` печатает каждое событие (`[buzzer] Play(n)`, `[buzzer] ON beepsLeft=…`); пищит, а лог молчит → это распайка, а не код |
| **RSSI-лог + CSV** | Раз в 5 с пишется RSSI по устройствам из WATCH (кольцевой буфер, 96 точек) → кнопка «Скачать RSSI-лог (CSV)» в WEB UI |
| **Живые настройки в NVS** | Всё, что меняешь в SETTINGS/через WEB UI, переживает перезагрузку |

Честно про WEB UI: Wi-Fi и BLE делят один радиомодуль, поэтому с включённой точкой
доступа скан идёт медленнее и RSSI грубее — в лабораторных измерениях лучше выключать AP.
Сон честно: если BLE-стек не даёт уйти в light sleep, вместо сна будет пауза `delay`
(об этом пишется в Serial один раз).

## Рамки проекта

* Работаем только с открытыми (broadcast) данными и с добровольными подключениями.
* Нет подмены MAC, нет деаутентификации, нет эксплойтов, нет «глушилок».
* `BLE FUN` рекламирует **твоё собственное** устройство (MAC чипа не меняется) —
  только имя в рекламном пакете.
* Используй там, где сканирование эфира разрешено, и только со своими устройствами.

## Сборка и заливка (проверено на железе)

* Плата: **ESP32 Dev Module** — проверено на ESP32-D0WD-V3 (rev 3.1), ядро `esp32:esp32 2.0.17`,
  USB-UART **CH340**, порт **COM3**.
* Библиотека: только **U8g2** (olikraus) — та, что уже стоит у тебя.
* **Tools → Partition Scheme → «Huge APP (3MB No OTA/1MB SPIFFS)»** — обязательно:
  прошивка занимает ~1.53 МБ (Bluedroid BLE + Wi-Fi + U8g2), в дефолтные 1.25 МБ она НЕ влезает
  (`Скетч слишком большой`).
* Остальное: Flash Size 4MB, Upload Speed 921600 (если не грузится — 115200).
* Скетч должен лежать по **пути без кириллицы** — иначе падает сборка esp-idf/CMake.
  Например `C:\BLE` (папка = `BLE.ino`). Копия для сборки уже лежит в `C:\BLE`.

Командной строкой (arduino-cli, без IDE):

```bash
arduino-cli compile --fqbn esp32:esp32:esp32:PartitionScheme=huge_app C:\BLE
arduino-cli upload  -p COM3 --fqbn esp32:esp32:esp32:PartitionScheme=huge_app C:\BLE
```

Что подтверждено на реальной плате: старт без перезагрузок, `Display: 128x64 rows=4`,
OLED отвечает на 0x3C, NVS читается, меню ходит по Serial, BLE-скан находит устройства в эфире
(`[i] BLE устройств в эфире: N`), IDENTITY включает рекламу (`[i] Реклама как "..."`).

## Управление по Serial (пока не подпаяны кнопки)

```
u / w   UP        l    OK (долгое нажатие)
d / s   DOWN      m    BACK (долгое нажатие)
o / Enter  OK     h    справка
b / Esc    BACK
```

Долгие нажатия нужны для: радар — открыть опции (источник BLE/Wi-Fi, развёртка);
WATCH — удалить устройство из списка; TIMED SCAN — старт.

| SCANNER | живой список (сортировка по RSSI, `*` = в WATCH), карточка устройства, CONNECT, WATCH |
| DEVICE | тип (вероятностно), MAC, действия, список GATT-сервисов после подключения |
| WATCH | избранное в NVS, FOUND/GONE + RSSI, LED/пищалка и сообщение, когда устройство появилось |
| IDENTITY | смена своего BLE-имени (UBPD/UNKNOWN/POCKET/…/CUSTOM «MY_UBPD» с редактором) |
| BLE FUN | 8 имён (кириллица в эфир), режимы SINGLE/CYCLE/RANDOM, реклама своего устройства |
| TIMED SCAN | интервал/длительность/запуски, цикл скан→пауза, лог находок |
| DEVICE TYPE | список устройств с вероятным типом и процентом уверенности |
| CLEAR SCAN | только телефоны/наушники/колонки/микрофоны, метки PH/HP/SP/MIC (v0.2.5) |
| SLEEP WATCH | OLED гаснет, редкие сканы, LED/пищалка на событие (v0.2) |
| SETTINGS | пищалка, порог сильного RSSI, сон, яркость, AP, сброс NVS (v0.2) |
| WEB UI | точка доступа + страница со всем перечисленным и CSV-логом (v0.2) |
| DIAGNOSTICS | батарея, RAM, Flash, BLE/Wi-Fi, uptime, версия, счётчики, ошибки |
| REMOTE | заглушка: AVRCP требует classic BT (план v0.3) |

## Честные технические оговорки

* **Радар — не направление.** Один ESP32 не может определить, откуда идёт сигнал.
  Показана только сила сигнала: **2 dBm = 1 пиксель**, −30 dBm = центр, −86 dBm = край.
  Угол точки — стабильный хэш MAC-адреса, а не реальный пеленг.
* **BLE и Wi-Fi по очереди.** Классический ESP32 делит один радиомодуль, поэтому в радаре
  источник либо BLE, либо Wi-Fi — одновременно не сканируем.
* **REMOTE (AVRCP)** возможен только по classic Bluetooth. Сам classic BT теперь есть
  (вкладка CLASSIC BT), но BLE + classic + Wi-Fi одновременно на классическом ESP32
  не тянутся, поэтому REMOTE — отдельный режим v0.5, пока на экране заглушка.
* **CONNECT** подключается только к устройствам, которые сами принимают соединение,
  и только читает открытые GATT-сервисы. Ничего не пишется и не эксплуатируется.
  Если устройство недоступно, экран может «замереть» до ~20 сек (таймаут стека BLE).
* **Почему у устройства нет имени.** Имя в BLE — необязательное поле рекламы. Apple-гаджеты,
  трекеры, ТВ-пульты и вообще всё, что уже подключено к телефону, часто его не передают
  (а некоторые отдают только в ответ на scan-запрос — UBPD делает активный скан и имя подхватит,
  если оно придёт позже). Тогда в списке показывается то, чем устройство всё же представилось:
  производитель по Company ID (`Apple`, `Samsung`, `Google`, `Xiaomi`…) и последние байты MAC.
  Если и производитель неизвестен — просто `AA:BB`. Это не ошибка сканера: проверено дампом
  сырых пакетов — поля имени (AD-тип `0x08`/`0x09`) в них нет, там только manufacturer/service data.
* **DEVICE TYPE** — это догадка по имени/сервисам/appearance, а не определение модели.
  Поэтому интерфейс пишет `ТИП: Audio 78%`.
* **BLE FUN** — своё устройство с фиксированным MAC. Имя в рекламе ≤ 24 байта
  (кириллица = 2 байта на символ), лишнее аккуратно отрезается по границе UTF-8.
* **TEMP_ENABLED = 0** по умолчанию: `temperatureRead()` есть не во всех версиях ядра.
  Хочешь температуру на экране — включи флаг; если линковка ругается, оставь 0.
* **BATT_ENABLED = 0**: сначала подпаяй делитель (например 100к + 100к), потом включи.
